## 建置與啟動

先關閉 LumasharpChecker，再執行：

```powershell
powershell -ExecutionPolicy Bypass -File .\建置.ps1
```

建置完成後執行 `啟動.vbs`，開啟 `App/LumasharpChecker.exe`。建置與啟動腳本使用固定通用檔名，不帶版本號。執行環境需有 `App/NativeR3` 原廠元件與隔離標記；配方、圖庫及站別設定保存在 App 目錄。

## 樣本還原點與容量控制

- 只有光源頁的「設為標準件並儲存參數」會自動建立樣本還原點，包含當張完整原圖與本站 ROI、基準亮度、允收模式及上下限。
- 每站保留最近 3 份，存放於 `App/recipes/<配方ID>/light-sample-history/stationNN`。原圖與設定都相同時不重複建立。
- 光源頁「還原樣本…」可一起還原本站原圖與光源參數，並清除該站舊判定。只接受同配方、同站別且校驗完整的還原點；不還原原生定位／選向／選面模型。
- 一般「儲存本站設定」、檢測、開關原生工具不建立樣本還原點。原生／原廠副本先比對內容；有變更才同步，成功校驗後清掉交易用副本。既有歷史備份不會被此變更自動刪除。
- 檢測 JSON/BMP 沿用 1.1.0.9 的 session 暫存清理機制；本次未將原生檢測改成 RAM-only。
- `建置.ps1` 將 bin/obj 放進本次專用的 Windows 暫存目錄，結束即清理；正式輸出留在 App，不再讓 Source 留下數百 MB 建置產物。

## 光源 ROI 初始化修正（2026-11-03）

新配方不再把同一組範本像素邊距套到所有站別，光源頁會依目前定位尺寸產生中央預設框。既有邊距無法容納於目前定位範圍時，編輯頁會產生可調整的框並顯示「尚未儲存」，不自動改寫配方。有效的既有 ROI 保持不變，也可按「重設 ROI」重新建立。

重新調整後，請用「設為標準件並儲存參數」重新計算基準亮度。正式檢測仍使用已儲存的 ROI，不會在檢測途中偷偷改框。

## 主畫面設定標準件

選好圖片與站別，在「標準件圖」按右鍵 →「設為第 N 站標準件」。點選後即定位目前圖片，沿用本站已存 ROI 與允收設定，計算本張基準亮度，保存原圖／參數並建立還原點；成功訊息會顯示配方、站別、圖片與基準亮度，不再開啟設定視窗。尚無可用 ROI 時，會按目前定位尺寸初始化；定位或量測失敗則不替換標準件。若要調整 ROI 或允收設定，使用「光源檢測」。左鍵仍載入已保存的標準件圖。

## 設定後立即複測

原生定位／選向／選面工具成功儲存並返回主畫面後，或在主畫面右鍵設標準件成功後，會自動測試目前圖片，更新影像、工具流程狀態、耗時、亮度與結果明細。光源頁有保存參數、設定／還原標準件時，關閉光源頁也會複測。沿用目前工具勾選狀態；這次單張複測不累加連續檢測統計。若原配方、站別或圖片已切換，會略過原圖的自動複測，避免顯示錯站結果。

## 訓練圖庫前綴與站號

可直接選 TrainingImage（僅一個產品前綴時自動辨識），或選產品 CCD 及其子資料夾。CCD1／CCD01 均支援；實際站號讀取 Origional／Original 下的數字資料夾，不把相機號當成站號，因此 CCD01 內可同時包含第 1 與第 5 站。多產品須選產品 CCD 資料夾，多版本仍由現有逐站選單選取，不自動混合；X／Y 不納入。舊式「匯入成配方」也使用相同辨識規則，同站多版本時會要求改用逐站選取入口。

## 清除舊圖庫來源

作業圖庫每站可按「清空本站」移除 ALL／OK／NG 指定；展開站別後也可只清除 OK 或 NG，此時 ALL 改由剩餘分類計算。清除會立即保存、失敗時回復原值，並清掉該站舊結果及目前圖片來源；保留原始檔、標準件與檢測參數。訓練圖庫逐站選單可選「不變更此站」或「清空本站圖庫」，例如新產品只有第 1～6 站時，可將第 7、8 站明確設為清空後一併套用。

## 全站最新圖片來源

「各站最新圖片設定」只選一次全站圖片來源（OK／NG／全部），即套用所有站；選擇會立即保存到目前 Recipe，切換配方／重開程式會恢復該配方的選擇。新配方及尚無此設定的舊配方預設 OK，不再沿用混合的逐站來源。每站張數仍獨立保存；所選分類無圖片時維持原先回退全部的行為。

## 全部結果與縮圖

全部結果顯示每張檢測當時記錄的亮度下限／上限，停用光源或缺少規格時顯示「—」。結果視窗可切換全部、OK、NG（含 Retest）或僅 Retest，並可開關縮圖；預設顯示全部縮圖。縮圖仍由虛擬化表格載入可見列。篩選 NG 可以減少結果視窗的圖片解碼，沒有改變檢測本身的計算或耗時。
