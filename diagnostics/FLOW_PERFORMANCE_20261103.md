# 流程效能分析與優化 — 1.1.0.14

2026-11-03，使用者反映工具合計 13.7 ms，但整體 50.3 ms。

結論：工具合計只涵蓋定位／選向／選面／光源演算法，整體另含完整配方檔案核對、原生讀圖、導正圖輸出、IPC 與畫面處理，兩個數值的範圍不同。

## 本次優化

- 每張圖仍比對完整檔案清單並逐檔做雙邊 SHA256；改用 Windows SHA256Cng，最多四路執行，保留原本 revision 排序與摘要內容，不以時間戳快取跳過核對。
- 原生輸出的 24-bit 未壓縮 BMP 直接讀取 ROI 涵蓋的資料段，使用 ArrayPool 暫借緩衝；HSV V 等於 max(B,G,R)，直接加總求平均，避免整張 BMP 解碼與 HSV 暫存 Mat。其他格式／BMP 格式保留原 Emgu CV 路徑，資料段大於 16 MiB 也使用舊路徑。
- 光源頁、設標準件與正式 FlowInspection 共用量測 helper。
- Native host 新增 ImageReadMs／FrameExportMs，工具耗時提示顯示原生讀圖與導正圖輸出，滑鼠停在「檢測合計／整體」可查看。
- 原生回傳驗證失敗時將原始回應寫入 Trace，方便診斷，不更動拒絕條件。

## 控制量測

配方 2222、第 1 站同一張已保存原圖的獨立複本；工具選擇 100（定位開、選向及選面關），光源採該站已存設定。每版 60 次，排除前 10 次暖機，取後 50 次中位數。測試包含每張完整配方比對、worker 影像讀寫／定位、光源量測；不包含 WPF 預覽／綁定／正式報告輸出，因此不可直接當作截圖「整體」的同條件數字。

|項目|1.1.0.13|1.1.0.14|
|---|---:|---:|
|核心總計|65.05 ms|48.91 ms|
|配方核對|19.62 ms|8.67 ms|
|原生往返|32.42 ms|30.73 ms|
|定位|6.71 ms|5.96 ms|
|光源|10.81 ms|6.99 ms|

此次核心總計縮短 24.8%。各分段各取中位數，並非單次同列相加。

部署後另測：核心 44.95 ms、配方核對 8.20 ms、原生讀圖 16.57 ms、導正圖輸出 2.66 ms。剩餘最大單段為 PNG 解碼；本版未加跨圖片快取，沒有用重複圖命中快取製造數字。

## 正確性與驗證

- 舊版、新版及部署後亮度皆為 245.47904970725008；擷取的原生導正 BMP 檔案 SHA256 一致。
- 平行 SHA256 結果與舊版 revision 完全一致；同檔案長度、同最後修改時間但變更內容，仍被拒絕，且保留 InvalidDataException 型別。
- 真正 Emgu CV 參考路徑對照：隨機色彩、24-bit 補齊行尾、ROI 邊界／內縮、bottom-up／top-down BMP、2×2、32-bit BMP fallback／PNG，平均差異 < 1e-10；原有零基準與超界測試通過。
- net472 x64 Slim 建置、git diff --check 通過。正式 App 三檔（主程式、PDB、native host）與發布成品核對 SHA256。
- 1.1.0.14 已更新並開啟，主視窗版本正確、Responding=true；未自動修改使用者配方或樣本，也未執行 UI 端到端計時。

下一步若仍要降低整體時間，應針對原生 PNG 解碼／預覽重複讀圖設計資料傳遞，並用不同圖片序列測量，不能只快取重複輸入；需要另外比較 IPC、生命週期與記憶體上限。
