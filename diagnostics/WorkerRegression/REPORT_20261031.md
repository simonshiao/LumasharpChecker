# 常駐原生流程修正驗證（2026-10-31）

已修正逐張啟動程序／重載 Recipe 的效能問題。測試只使用隔離副本，正式參數、門檻與原廠 source 均未修改，未操作使用者視窗。

## 改動

- LumaNativeFlowHost 新增 stdin/stdout JSON-line worker；舊單次 CLI 保留相容。原生 DLL 繼續隔離在子程序。
- 同一 Recipe/站別/內容版本重用 CVInspection。每張開始前還原 LocateParam、SelectWayParam、SelectFaceParam 與工具旗標，清空選面暫存，避免前張翻轉／結果污染後張。
- 每張仍以 SHA256 比對快照與原生副本全部檔案；CLI 驗證只在內容或 Runtime 變更時重做。參數版本由實際內容計算，未以檔案時間或大小當作真實內容。
- 換站、換配方或內容版本不同即重新載入；開啟原生編輯器與程式退出時關閉 worker。
- 每工作使用唯一 ID，驗證 Recipe、站別、圖片及程序 ID；異常、舊回應、中斷、25 秒逾時皆拒絕成功判定並清理。下次請求重新建立程序。
- native stderr 持續排空但不累積成無界字串，防止 pipe 塞滿與常駐程序記錄膨脹。
- 預覽影像改為無損 BMP；沒有降低解析度或改演算法。結果節點新增整張流程耗時，首張初始化成本照實納入。

## 實測

## 一致性與失敗保護

- 22/22 圖片新舊 Exit、定位框 X/Y/W/H、選向狀態與明細、選面狀態／面別一致。
- 22/22 完整輸出影像解碼後所有 BGR 像素 SHA256 一致；光源 ROI HSV V 平均值完全一致。PNG/BMP 僅容器不同。
- 所有後續圖片使用同一個 worker PID，RecipeReused=True；切換站別後正確重新載入。
- 工具使用旗標切換及翻轉後再次檢測，不殘留上一張狀態。
- 只改原生副本，即使長度與時間戳相同，仍拒絕執行。
- 同時修改快照與副本的 LocateWidthMax 為 0（只在測試副本），下一張立即重新驗證／載入並回傳 FAIL；復原後恢復成功，證明不使用舊快取。
- 平行送出兩個請求仍正確序列化，結果對應各自圖片。
- 損壞影像與外部終止 worker 後，下一次檢測可恢復。
- 模擬大量 stderr 加錯誤工作 ID，回應被拒絕且不阻塞。
- 模擬卡死 worker，25 秒逾時後終止，恢復真 worker 後可再次檢測。
- 100 張連續執行全部成功；記憶體記錄見 memory.json。測試中 GC 有回收，沒有單調無限成長；這不代表已完成長時間機台壓力驗收。
- 明確 Shutdown 後 worker 正常退出，未留下測試程序。
